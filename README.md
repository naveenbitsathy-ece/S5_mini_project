# MATLAB and FPGA-Based Digital Signal Processing Using ZedBoard

**Real-Time Moving Average Filtering, FFT Analysis, FPGA Verification, and Machine Learning Integration**

## 📌 Project Overview

This project demonstrates a Digital Signal Processing (DSP) workflow using MATLAB and the Xilinx ZedBoard based on the Zynq-7000 SoC.

A noisy signal is generated in MATLAB, converted into 16-bit digital samples, and transmitted to the FPGA through UART communication. A 12-point moving-average filter implemented in the FPGA processes the incoming samples. The filtered results are returned to MATLAB, where they are compared against a MATLAB reference implementation.

The project also performs frequency-domain analysis using the Fast Fourier Transform (FFT), sends the FPGA-processed samples to an external machine-learning server for prediction, and exports the experimental results to an Excel workbook.

The main objective is to understand the complete workflow from signal generation and digital filtering to hardware verification, frequency analysis, and ML integration.

## 🎯 Project Objectives

- Generate a synthetic signal with multiple frequency components and measurement noise.
- Convert the generated signal into 16-bit unsigned integer samples.
- Establish UART communication between MATLAB and the ZedBoard.
- Implement and verify a 12-point moving-average filter on the FPGA.
- Compare FPGA output against a MATLAB reference model.
- Analyze the filtered output in the frequency domain using FFT.
- Upload FPGA-processed samples to an external ML server.
- Visualize signal behavior and filtering errors.
- Export experimental data and summary metrics to Excel.

## ⚙️ Working Principle

### 1. Synthetic Signal Generation

MATLAB generates a synthetic vibration/displacement signal containing:

- Slowly varying baseline drift.
- Multiple sinusoidal and cosine components.
- Random measurement noise.

The clean signal is formed by combining the drift and oscillation components. Random noise is then added to simulate measurement disturbances.

The random number generator is initialized using a fixed seed so that the same test signal can be reproduced across runs.

### 2. Signal Scaling and Quantization

The generated signal is represented in physical units, such as millimetres. Since the FPGA receives digital samples, the signal is mapped to the unsigned 16-bit range.
### Signal Scaling and Quantization

The input signal is mapped to a 16-bit unsigned integer range using:

$$
q[n] = \frac{x[n]-x_{\min}}{x_{\max}-x_{\min}} \times 65535
$$

The resulting value is rounded to the nearest integer and clipped to the range:

$$
0 \leq q[n] \leq 65535
$$

This allows each sample to be transmitted as two 8-bit bytes over UART.

### 3. UART Communication

MATLAB communicates with the ZedBoard through a serial interface.

The communication sequence is:

1. Open the configured COM port.
2. Configure the baud rate and serial parameters.
3. Clear pending input and output data.
4. Send zero samples to flush the filter's stored history.
5. Split each 16-bit sample into low and high bytes.
6. Transmit the bytes to the FPGA.
7. Receive the two-byte filtered output.
8. Reconstruct the 16-bit result.

For the uploaded implementation, the configured baud rate is 115200 baud. The COM port must match the UART interface assigned to the board.

### 4.Moving Average Filter

The 12-point moving-average filter smooths rapid variations in the input signal by calculating the average of the current sample and the previous 11 samples.

**Mathematical Expression:**

$$
y[n] = \frac{1}{12}\sum_{k=0}^{11} x[n-k]
$$

**Where:**
- $x[n]$ represents the current input sample.
- $y[n]$ represents the filtered output sample.
- $k$ is the sample index within the filter window.
- $12$ is the number of samples in the moving-average window.

**Working Principle:**

The filter adds 12 consecutive input samples and divides their sum by 12 to produce the output.

$$
y[n] = \frac{x[n]+x[n-1]+\cdots+x[n-11]}{12}
$$

This averaging operation reduces rapid fluctuations and helps smooth noise in the input signal.

### 5. MATLAB Reference Verification

MATLAB independently computes the expected moving-average output.

The FPGA output is then compared with this reference:

\[
e[n]=y_{\mathrm{FPGA}}[n]-y_{\mathrm{MATLAB}}[n]
\]

Two metrics are calculated:

**Maximum absolute error**

\[
E_{\max}=\max_n |e[n]|
\]

**Mismatch count**

\[
M=\sum_n \mathbf{1}(e[n]\neq0)
\]

If the maximum error and mismatch count are both zero, every FPGA output matches the MATLAB reference for the tested samples.

### 6. FFT Frequency-Domain Analysis

The FPGA output samples are processed in MATLAB using the Fast Fourier Transform.

Before computing the FFT, the mean is removed to reduce the DC component.

The magnitude spectrum is calculated and displayed against frequency.

### Frequency Resolution

$$
\Delta f = \frac{F_s}{N}
$$

### Nyquist Frequency

$$
f_N = \frac{F_s}{2}
$$


The FFT plot helps examine the frequency content remaining after moving-average filtering.

> The FFT in this project is calculated in MATLAB, not by a dedicated FPGA FFT accelerator.

### 7. Machine Learning Integration

The filtered FPGA output is serialized into a JSON payload. A temporary Python client sends this payload to the configured server using an HTTP POST request.

The server response can contain:

- Processing status.
- Number of samples received.
- Number of windows evaluated.
- Predicted classes for each window.
- Prediction probabilities, when provided by the server.

The ML model, feature extraction, training procedure, and prediction labels depend on the external server implementation and should be documented separately if included in the repository.

These plots help evaluate filtering behavior, output accuracy, and the frequency components present in the filtered signal.

## 🧪 Verification Strategy

The project uses MATLAB as a software reference to validate the hardware implementation.

The verification procedure is:

1. Generate a known input sequence.
2. Calculate the expected moving-average output in MATLAB.
3. Transmit the same sequence to the FPGA.
4. Receive the FPGA output.
5. Compare both output sequences sample by sample.
6. Calculate maximum absolute error and mismatch count.
7. Inspect the plots and exported results.

Potential sources of mismatches include incorrect byte ordering, UART synchronization errors, different integer-division behavior, arithmetic overflow, and differences in the filter's initial state.

## TCL script for vivado 

## Vivado Tcl Automation

Automated FPGA design flow using Tcl scripting in Vivado 2020.1 / 2025.1.

### Automated Workflow

1. Project verification
2. Synthesis
3. Implementation
4. Bitstream generation
5. Build status and bitstream location reporting

### Tcl Script

Save the following script as `run_fpga_flow.tcl`.

```tcl
# =========================================================
# Vivado Tcl Automation
# Synthesis -> Implementation -> Bitstream Generation
# Compatible with Vivado 2020.1 / 2025.1
# =========================================================

set_param general.maxThreads 8

# 1. Check Vivado Project
if {[current_project -quiet] eq ""} {
    puts "ERROR: No Vivado project is open."
    error "Please open the .xpr project first."
}

set project_name [get_property NAME [current_project]]
puts "Project: $project_name"

# 2. Run Synthesis
puts "\n===== STARTING SYNTHESIS ====="

reset_run synth_1
launch_runs synth_1 -jobs 8
wait_on_run synth_1

set synth_status [get_property STATUS [get_runs synth_1]]
puts "Synthesis Status: $synth_status"

if {![string match "*Complete*" $synth_status]} {
    error "Synthesis failed. Check Vivado messages."
}

# 3. Run Implementation and Bitstream Generation
puts "\n===== STARTING IMPLEMENTATION ====="

reset_run impl_1
launch_runs impl_1 -to_step write_bitstream -jobs 8
wait_on_run impl_1

set impl_status [get_property STATUS [get_runs impl_1]]
puts "Implementation Status: $impl_status"

if {![string match "*Complete*" $impl_status]} {
    error "Implementation or bitstream generation failed."
}

# 4. Display Bitstream Location
puts "\n===== FLOW FINISHED ====="

set bit_files [get_files -quiet -all *.bit]

if {[llength $bit_files] > 0} {
    foreach bit_file $bit_files {
        puts "Bitstream: $bit_file"
    }
} else {
    puts "Check the implementation run directory."
}

puts "Synthesis, implementation and bitstream flow completed."
```

### How to Execute

1. Open your Vivado project (`.xpr`).
2. Open the Tcl Console.
3. Navigate to the directory containing the script.
4. Execute:

```tcl
source run_fpga_flow.tcl
```

### Expected Output

- Synthesis completed successfully.
- Implementation completed successfully.
- FPGA bitstream (`.bit`) generated.
- Bitstream location displayed in the Tcl Console.
